# 11 · 真机测试矩阵

> 适用范围：v1.0 发布候选（Android 7.0+ / iOS 15+）。
> 目标：在缺少自动化真机农场的情况下，用最小设备集覆盖权限、后台保活、
> 推送、地图与弱网场景，并留下可复查的证据。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 构建 | `flutter build apk --release` / `flutter build ipa`，非 debug |
| 服务器 | Traccar 6.x，可访问 `/api/server`、`/api/socket`、`/api/commands/send` |
| 地图 | 已配置高德 Android/iOS Key，包名/Bundle ID 与 Key 绑定 |
| 推送 | `PUSH_PROVIDER=jpush` 或 `fcm`，网关与 Traccar webhook 已通 |
| 账号 | 至少 1 个管理员、1 个普通用户、1 个只读用户 |
| 设备 | 以下矩阵中至少 1 台 Android 国产 ROM + 1 台原生 Android + 1 台 iPhone |
| 日志 | 诊断页可复制日志；Android 可 `adb logcat`，iOS 可 Console.app |

## 2. 设备矩阵

| 编号 | 平台 | 厂商 / 型号 | 系统 | 重点 |
|---|---|---|---|---|
| A1 | Android | 小米 / Redmi | HyperOS / Android 14+ | 自启动、省电策略、厂商推送 |
| A2 | Android | 华为 / 荣耀 | HarmonyOS / Android 12+ | 应用启动管理、后台活动 |
| A3 | Android | OPPO / 一加 / realme | ColorOS | 电池管理、自启动 |
| A4 | Android | vivo / iQOO | OriginOS | 后台耗电管理 |
| A5 | Android | 三星 | One UI 6+ | 休眠应用、后台限制 |
| A6 | Android | Pixel / 原生 | Android 14/15 | 权限模型、Doze、FCM |
| I1 | iOS | iPhone 13+ | iOS 17/18 | 始终定位、后台刷新、APNs |
| I2 | iOS | iPhone SE | iOS 15 | 最低版本兼容、小屏布局 |

> 若时间有限，最低覆盖：A1、A2、A6、I1。其余厂商在发布前各跑 1 次
> “权限 + 2 小时后台上报 + 锁屏推送”冒烟即可。

## 3. 用例清单

### 3.1 安装与启动

| ID | 步骤 | 期望 |
|---|---|---|
| INS-01 | 全新安装，首次启动 | 隐私政策/地图 SDK 说明先于地图与推送初始化 |
| INS-02 | 拒绝地图隐私授权 | 显示说明卡片，不崩溃、不初始化高德 |
| INS-03 | 同意后进入地图 | 底图加载，无白屏；无 Key 时显示缺少 Key 提示 |
| INS-04 | 冷启动计时（`--profile`） | < 2.5s（中端机） |
| INS-05 | 升级安装（保留数据） | 会话、服务器档案、语言、离线缓存保留 |

### 3.2 登录与服务器

| ID | 步骤 | 期望 |
|---|---|---|
| AUTH-01 | 密码登录 | 成功后进入地图，Token 安全存储 |
| AUTH-02 | 错误密码 | 可读错误，不泄露服务端细节 |
| AUTH-03 | Token 登录 | 直接进入；失效时回登录页 |
| AUTH-04 | QR 导入服务器 | 地址/账号正确填充 |
| AUTH-05 | 自签名证书 | 明确提示证书不受信任，可返回修改 |
| AUTH-06 | 服务器不可达 | 有错误态与重试；已缓存数据仍可查看 |

### 3.3 权限向导

| ID | 步骤 | 期望 |
|---|---|---|
| PERM-01 | 通知 → 前台定位 → 后台定位逐步允许 | 每步状态正确，完成后可开始上报 |
| PERM-02 | 某一步永久拒绝 | 显示“去设置”，返回后状态刷新 |
| PERM-03 | 运行中撤销定位 | 上报停止并在诊断页给出结论 |
| PERM-04 | 点击“厂商保活指南” | 识别厂商并展示对应路径（小米/华为/OPPO/vivo/三星） |
| PERM-05 | 关闭电池优化 | 诊断页电池状态变为“已豁免” |

### 3.4 后台上报（核心）

| ID | 步骤 | 期望 |
|---|---|---|
| TRK-01 | 前台开始上报，走动 10 分钟 | 轨迹连续，间隔符合配置 |
| TRK-02 | 锁屏 2 小时 | 服务端持续收到位置；通知栏常驻 |
| TRK-03 | 锁屏 24 小时（过夜） | 断点 < 5 分钟；耗电 ≤ 6% |
| TRK-04 | 72 小时 | 无崩溃；内存无持续增长；可被系统回收后恢复 |
| TRK-05 | 关闭 Wi-Fi/移动网络 30 分钟 | SDK 本地缓存，恢复后补传 |
| TRK-06 | 强杀应用后重新打开 | 按配置恢复上报；不重复注册设备 |
| TRK-07 | 重启手机 | 开机后自动恢复（若系统允许） |
| TRK-08 | 省电模式 / 低电量 | 行为可解释，诊断页提示风险 |
| TRK-09 | 修改上报间隔 / 距离 / 心跳 | 立即生效并持久化 |

## 5. 收集命令

```bash
# Android：设备信息、电量、崩溃
adb shell getprop ro.product.manufacturer
adb shell dumpsys deviceidle whitelist | grep trackerone
adb logcat -d | grep -Ei "trackerone|traccar|FATAL|ANR" > trackerone-logcat.txt

# iOS：查看后台刷新与定位授权
xcrun simctl spawn booted log stream --predicate 'process == "Runner"'   # 模拟器仅辅助
# 真机请用 Xcode → Devices and Simulators → Open Console
```

## 6. 通过标准

- P0 用例 100% 通过；P1 允许 ≤ 2 个已知问题且有规避方案。
- Android 与 iOS 各至少 1 台设备完成 24h 后台上报。
- 国产 ROM 至少 2 家完成锁屏推送。
- 地图 500/1000 设备达到 ≥ 30fps 或记录明确的性能风险与降级策略。
- 无崩溃、无 ANR、无隐私合规阻断项。
