# 06 · 开发计划与排期

## 1. 假设

| 项 | 假设 |
|---|---|
| 团队 | 1 名 Flutter 主程（全职）+ 0.5 名后端/测试支持 |
| 周期 | 12 周（含 15% buffer）；双人并行可压缩到 8 周 |
| 后端 | 使用现有 Traccar 6.16，仅做配置与联调，不改代码 |
| 设计 | 有基础设计稿；无专职 UI 时按 02 文档实现 |
| 发布 | Android + iOS 同步；首发中国大陆；备案与软著并行启动 |
| 节奏 | 2 周一个 Sprint，共 6 个 Sprint |

## 2. 里程碑

```
W1   W2-3    W3-6      W7-8      W9-10     W11-12
M0 → M1  →  M2   →   M3   →   M4    →   M5
验证  骨架   跟踪+地图  历史+推送  打磨     发布
```

| 里程碑 | 目标 | 退出标准 |
|---|---|---|
| **M0 技术验证** | 四个高风险点跑通 | SDK 后台 24h 有数据；登录/WS 通；高德地图真机正常；极光后台/冷启动可达 |
| **M1 骨架** | 可登录、可配置、可导航 | 服务器档案 + 登录 + 路由守卫 + CI 绿 |
| **M2 核心** | 可上报、可实时查看 | 本机上报 + 地图实时 + 设备详情 + 离线缓存 |
| **M3 闭环** | 可回溯、可告警 | 历史回放 + 事件列表 + 推送直达 + 指令 |
| **M4 可运维** | 可诊断、可发布候选 | 诊断页 + 多语言 + 性能达标 + 安全自查 |
| **M5 发布** | 上架 | 测试矩阵通过 + 商店材料 + 灰度 |

## 5. 关键路径

```
SDK 验证 ──▶ 跟踪核心 ──▶ 真机回归 ──▶ 发布
                 │
地图验证 ──▶ 实时地图 ──┘
                 │
API 验证 ──▶ 认证/历史/事件 ──▶ 推送/指令 ──┘
```

**不能并行压缩的点**：

- 后台定位真机验证（必须跑满 24h/72h）。
- 商店审核（尤其后台定位申报）。
- iOS 后台行为验证（模拟器无效）。

## 7. 角色与协作

| 角色 | 职责 |
|---|---|
| Flutter 主程 | 架构、核心功能、性能、发布 |
| 后端/运维（0.5） | 服务器配置、推送网关、Traccar 补丁、反代、联调、日志 |
| 测试（0.5） | 用例、真机矩阵、回归、发布验收 |
| 设计（按需） | 视觉、图标、商店素材 |
| 产品（兼任） | 需求优先级、验收、隐私文案 |

**协作节奏**

- 每日 15 分钟同步。
- 每周 Demo（可运行版本）。
- 每个 Sprint 结束评审 + 回顾。
- 缺陷：P0 当天、P1 本 Sprint、P2 排期。

## 8. Definition of Ready / Done

### Ready

- 需求有明确验收标准。
- 依赖（接口/设计/权限）已确认。
- 影响范围与埋点已列出。

### Done

- 代码通过 analyze / format / test。
- 单元测试覆盖核心逻辑；关键流程有 Widget/集成测试。
- 真机验证（至少 Android + iOS 各一台）。
- 错误态、空态、离线态处理完成。
- 文案进 ARB，无硬编码。
- 埋点与日志脱敏。
- 文档/ADR 更新。
