# 01 · 产品需求文档（PRD）

## 1. 角色与使用模式

应用首次启动时让用户选择模式，后续可在设置中切换：

| 模式 | 说明 | 默认首页 |
|---|---|---|
| **跟踪本机** | 只把本机作为 GPS 设备上报，不需要账号 | 跟踪面板 |
| **查看设备** | 登录服务器，查看/管理已有设备 | 地图 |
| **两者都要** | 既上报本机，也查看设备（推荐） | 地图 + 本机卡片 |

模式只影响默认导航与引导，不限制功能；用户随时可以开启另一侧能力。

## 3. 关键需求详述与验收标准

### 3.1 服务器档案（AUTH-01/02/03/11）

**字段**

| 字段 | 说明 | 示例 |
|---|---|---|
| `name` | 显示名称 | 我的服务器 |
| `apiBaseUrl` | REST / WebSocket 根地址 | `https://track.example.com` |
| `reportUrl` | 位置上报地址 | `https://track.example.com:5055` |
| `allowSelfSigned` | 是否允许自签名证书（默认关） | `false` |
| `preset` | 是否官方演示服务器 | `false` |

**自动推导规则**

1. 用户输入 `https://host` → API = 原值；上报 = `https://host:5055`。
2. 输入 `https://host:8082` → API = 原值；上报 = `https://host:5055`。
3. 输入带路径（反向代理）→ API 保留路径；上报使用同 host + 默认端口，允许用户覆盖。
4. 探测 `/api/server` 成功后展示服务器名称与版本；失败给出可操作错误。

**验收**

- [ ] 输入一个地址即可完成配置，无需分别填写两个地址。
- [ ] 地址格式错误、TLS 错误、超时分别有明确提示。
- [ ] 二维码内容为 URL 或 JSON 时都能解析。
- [ ] 配置保存在本地，重启后保留；Token 不写入普通偏好。

### 3.2 登录与会话（AUTH-04/05/06/10）

**流程**

```
POST /api/session            (form: email, password)  → Set-Cookie
POST /api/session/token      (form: expiration?)      → text/plain token
GET  /api/session?token=...  (校验)                    → User
WebSocket /api/socket?token=...                       → 实时数据
```

**要求**

- 密码登录使用 Cookie 完成 1→2 步，Token 落盘 Secure Storage。
- 后续所有 REST 使用 `Authorization: Bearer <token>`。
- 登录成功缓存用户信息（id、name、email、attributes）。
- 401 时清除 Token 并回到登录页；网络错误不强制登出。
- 退出登录调用 `POST /api/session/token/revoke`，失败也清理本地。

**验收**

- [ ] 正确凭证 3 秒内进入首页（正常网络）。
- [ ] 错误凭证提示"邮箱或密码错误"，不泄露账号是否存在。
- [ ] 断网时可用缓存进入只读界面，顶部提示离线。
- [ ] 生物识别开启后，冷启动读取 Token 前必须验证。

### 3.3 本机绑定（TRK-01/02）

**规则**

- 首次生成 8 位数字 uniqueId（与旧 Client 兼容），允许用户修改。
- 登录后点击"绑定本机"：
  1. `GET /api/devices?uniqueId=<id>` 查找；
  2. 不存在则 `POST /api/devices` 创建设备（需要权限）；
  3. 将设备 id 存入本地，地图高亮"本机"。
- 无创建权限时，展示"请联系管理员添加设备 <id>"并提供复制。

**验收**

- [ ] 已存在设备时直接绑定，不重复创建。
- [ ] 创建失败有明确原因（权限/重名/网络）。
- [ ] 绑定后地图在 10 秒内出现本机位置（已开启上报）。

### 3.4 跟踪控制与配置（TRK-03～TRK-10）

**状态机**

```
未配置 → 已停止 → 启动中 → 运行中 ⇄ 已暂停（系统限制）
                     ↘ 失败（权限/配置）
```

**配置项与默认值**

| 项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| accuracy | medium | highest/high/medium/low | 精度与功耗 |
| intervalSeconds | 300 | 10–86400 | 最大上报间隔 |
| distanceMeters | 75 | 0–10000 | 最小位移触发 |
| angleDegrees | 0 | 0–180 | 转向触发，0 关闭 |
| heartbeatIntervalSeconds | 0 | 0–3600 | iOS 后台心跳 |
| buffer | true | bool | 离线队列 |
| stopDetection | true | bool | 静止暂停 GPS |
| wakeLock | false | bool | Android 唤醒锁 |
| preferPlatformProviders | false | bool | 强制系统定位 |

**预设**

| 预设 | 精度 | 间隔 | 距离 | 停止检测 |
|---|---|---|---|---|
| 步行 | high | 60s | 20m | 开 |
| 驾车 | high | 30s | 50m | 开 |
| 资产 | medium | 600s | 200m | 开 |
| 高频 | highest | 10s | 0m | 关 |
| 省电 | low | 1800s | 500m | 开 |

**验收**

- [ ] 修改配置后无需重启跟踪即可生效（`setConfig`）。
- [ ] 开始上报前完成权限检查；拒绝时展示原因与设置入口。
- [ ] 运行中锁屏 30 分钟仍有心跳（真机矩阵验证）。
- [ ] 强制停止应用后重新打开，状态与实际一致。
- [ ] 队列积压 > 100 时在跟踪页提示。

### 3.5 实时地图（MAP-01～MAP-09）

**数据流**

- 首屏：`GET /api/devices` + `GET /api/positions`（最新）→ 渲染。
- 增量：`/api/socket?token=` → `{positions:[...]}`、`{devices:[...]}`、`{events:[...]}`。
- 断线：指数退避重连（1s → 30s，带抖动）；恢复后重新拉取快照。

**交互**

- 单击标记：底部卡片（名称、状态、速度、电量、最后更新、操作）。
- 长按地图：快捷"在此创建围栏"（P1）。
- 双击/双指：缩放；单指拖动后退出跟随。
- 聚合：> 50 个标记时按网格聚合，点击展开。
- 尾迹：最近 50 个点，渐变透明度，可关闭。

**性能预算**

| 场景 | 目标 |
|---|---|
| 500 设备首屏 | < 2s 可交互 |
| 1000 设备标记更新 | ≥ 30fps |
| 地图平移/缩放 | 60fps（中端机） |
| 内存占用（500 设备） | < 250MB |

**验收**

- [ ] 设备位置更新在 WebSocket 连接正常时 10 秒内反映。
- [ ] 无网络时展示缓存位置并标注"最后更新时间"。
- [ ] 地图供应商可通过配置切换，不需要改业务代码。

### 3.6 历史回放（HIS-01～HIS-08）

**要求**

- 查询：`GET /api/positions?deviceId=&from=&to=`，分页/分段加载。
- 抽稀：> 5000 点时按距离/时间抽稀，保证渲染性能。
- 回放：时间轴 + 播放倍速（1x/2x/4x/8x）+ 进度拖动。
- 停留：基于速度与半径聚类，展示起止时间与时长。
- 图表：速度、海拔、电量三条曲线，联动游标。
- 导出：GPX / KML / CSV，走系统分享。

**验收**

- [ ] 7 天数据在 3 秒内完成首屏绘制。
- [ ] 回放过程中地图跟随平滑，无明显卡顿。
- [ ] 导出的 GPX 可被第三方工具打开。

### 3.7 事件与推送（EVT-01～EVT-06）

**推送数据（通道无关）**

App 只解析归一化后的业务字段：

```json
{
  "eventId": "12345",
  "deviceId": "42",
  "type": "geofenceEnter",
  "title": "围栏进入",
  "body": "京A·12345 进入「公司」"
}
```

| 通道 | 承载方式 |
|---|---|
| 极光（中国大陆） | `notification.android.extras` / `notification.ios.extras` |
| FCM（海外/开发） | `data` |
| 应用内 | WebSocket `{events:[...]}` |

**要求**

- 前台：应用内横幅 + 事件流更新，不弹系统通知。
- 后台：系统通知，点击带 `eventId` 进入事件详情。
- 冷启动：推送 SDK 的「启动参数」在登录完成后再消费，避免路由竞态。
- 通知权限：首次进入地图后请求，拒绝也可用应用内事件。
- 同一事件去重（eventId）。
- 中国大陆包不初始化 Firebase，未配置推送时自动降级为 `NoopPushGateway`。

**验收**

- [ ] 三种生命周期下点击推送都能到达正确事件。
- [ ] 未登录时点击推送，登录后继续跳转。
- [ ] 重复推送不产生重复列表项。

### 3.8 远程指令（DEV-04/05/06）

**发送**

- `POST /api/commands/send`（type、deviceId、attributes）。
- 支持类型从 `GET /api/commands/types` 获取并按设备协议过滤。
- 结果：排队/已发送/失败；失败展示服务端消息。

**接收（本机）**

- 推送 `extras.command`：`positionSingle`、`positionPeriodic`、`positionStop`、`factoryReset`。
- 执行后通过位置上报或事件回执（如服务端支持）。
- `factoryReset` 需二次确认，清空本地敏感配置。

**验收**

- [ ] 指令发送后 5 秒内 UI 显示状态。
- [ ] 本机在后台收到指令能执行（不要求打开 App）。
- [ ] 高风险指令有确认与审计日志。

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标 |
|---|---|
| 冷启动到可交互 | < 2.5s（中端 Android） |
| 登录到地图 | < 3s |
| 地图帧率 | 60fps（常规），≥ 30fps（1000 设备） |
| 历史查询 7 天 | < 3s 首屏 |
| 安装包 | Android < 40MB，iOS < 60MB |
| 内存峰值 | < 300MB |

### 4.2 可靠性

- 上报：断网、切换网络、进程被杀、重启后不丢点（SDK 队列）。
- 实时：WebSocket 断线自动重连，恢复后补快照。
- 缓存：设备/位置/事件本地可读，冷启动不白屏。
- 幂等：重复位置/事件不产生重复 UI。

### 4.3 安全

- Token、密码仅存 Secure Storage；日志脱敏。
- 默认强制 HTTPS；自签名需显式开启并提示风险。
- 可选证书固定（企业版）。
- 生物识别保护 Token 读取。
- 退出登录清理缓存与 Token。
- 遵循 OWASP MASVS-L1。

### 4.4 隐私与合规

- 后台定位必须明确告知用途、频率、目的地。
- 提供"一键停止上报"和"删除本地数据"。
- 隐私政策覆盖：位置、设备信息、崩溃日志、推送标识。
- 不接入广告 SDK；分析数据匿名化。
- 中国大陆：
  - 行踪轨迹属于敏感个人信息，后台定位需**单独同意**；
  - 首次启动展示隐私政策，同意前不初始化地图/推送/统计 SDK；
  - 提供个人信息收集清单与第三方 SDK 清单（高德、极光、Bugly 等）；
  - 提供账号注销与数据删除入口；
  - 不使用境外服务器与境外 SDK 处理中国大陆用户数据；
  - 展示 APP 备案号与地图审图号。

### 4.5 可用性

- 支持 35 种语言（继承 Client ARB），RTL。
- 动态字体、TalkBack/VoiceOver 标签。
- 颜色对比度 ≥ 4.5:1。
- 单手可达主要操作；横屏/平板自适应。

### 4.6 兼容性

| 平台 | 最低 | 目标 |
|---|---|---|
| Android | API 24 (7.0) | API 36 |
| iOS | 15.0 | 18.x |
| Traccar Server | 6.0 | 6.16+ |

国产 ROM 重点：小米、华为/荣耀、OPPO、vivo、三星。
