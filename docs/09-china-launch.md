# 09 · 中国大陆落地方案

> 首发市场：中国大陆。本文把地图、推送、合规、备案、商店五个硬约束落到可执行动作。
> 相关代码：`lib/core/map/`、`lib/core/push/`、`server/`。

## 2. 地图

### 2.1 选型对比

| 维度 | 高德 | 腾讯 | 百度 |
|---|---|---|---|
| 测绘资质 | 甲级导航电子地图（以官方公示为准） | 甲级 | 甲级 |
| 官方 Flutter 插件 | `amap_map`（Apache-2.0，verified publisher，持续维护） | `flutter_tencent_map`（社区维护，更新慢） | 无官方，社区包质量参差 |
| 坐标系 | GCJ-02 | GCJ-02 | BD-09 |
| 逆地理 / POI | 完善 | 完善 | 完善（POI 最强） |
| 离线地图 | 支持（需额外接入） | 支持 | 支持 |
| 海外覆盖 | 弱 | 弱 | 弱 |
| 接入成本 | 低 | 中 | 高（坐标 + 插件） |
| 生态资料 | 多 | 中 | 少 |

**结论：高德。** 理由：

1. `amap_map` 是唯一维护活跃、许可证干净（Apache-2.0）的国内地图 Flutter 插件；
2. 高德与腾讯同为 GCJ-02，切换供应商时**不需要动数据层**；
3. 百度 BD-09 需要在 GCJ-02 上再偏移，轨迹回放、点选建围栏、导出都会多一层转换，收益不足以抵消成本。

### 2.2 接入清单

| # | 事项 | 说明 |
|---|---|---|
| M1 | 注册高德开放平台账号 | 个人或企业主体，企业认证后配额更高 |
| M2 | 创建应用 | 应用名称与包名需与最终发布一致 |
| M3 | 申请 Android Key | 绑定**包名 + SHA1**；debug 与 release 签名不同，需分别申请 |
| M4 | 申请 iOS Key | 绑定 **Bundle ID** |
| M5 | 配置 Key | 通过 `--dart-define=AMAP_ANDROID_KEY / AMAP_IOS_KEY` 注入，不入库 |
| M6 | 隐私授权 | 用户同意隐私政策后才 `updatePrivacyAgree`，再 `init` |
| M7 | 审图号 | 从高德开放平台获取底图审图号，在「关于」页展示 |
| M8 | 商用授权 | 确认配额与商用条款；超配额需购买 |

> ⚠️ **改包名 = 重新申请 Key。** 这是把 `com.example.trackerone` 换成正式包名的又一个理由，越早改越省事。

### 2.3 代码结构

| 文件 | 职责 |
|---|---|
| `lib/core/map/geo_point.dart` | 不可变坐标点 + 坐标系枚举 + 球面距离 |
| `lib/core/map/coordinate_transform.dart` | WGS-84 / GCJ-02 / BD-09 互转（纯 Dart，可单测） |
| `lib/core/map/map_models.dart` | 设备标记、尾迹、相机目标 |
| `lib/core/map/map_provider.dart` | 供应商选择与样式配置 |
| `lib/core/map/map_privacy_consent.dart` | 地图 SDK 隐私授权持久化 |
| `lib/core/map/amap/amap_bootstrap.dart` | 高德 SDK 初始化与合规顺序 |
| `lib/core/map/amap/amap_tracker_map.dart` | 高德渲染实现（内部做坐标转换） |
| `lib/core/map/tracker_map_view.dart` | 唯一地图入口，业务层只依赖它 |

业务层永远传 WGS-84：

```dart
TrackerMapView(
  markers: devices
      .map((d) => MapDeviceMarker(
            deviceId: d.id,
            label: d.name,
            point: GeoPoint(p.latitude, p.longitude), // WGS-84
            course: p.course,
            online: d.isOnline,
          ))
      .toList(),
)
```

### 2.4 已知坑

| 问题 | 处理 |
|---|---|
| Android targetSdk ≥ 30 返回地图页闪退 | `application` 加 `android:allowNativeHeapPointerTagging="false"` |
| 模拟器 GL 崩溃 | 切换模拟器图形加速为 Software，或直接用真机 |
| iOS 12+ | 我们最低 iOS 15，满足 |
| Key 与包名绑定 | 换包名/换签名必须重新申请 |
| 隐私检测 | 必须先同意后初始化，顺序写死在 `TrackerMapView` |
| 瓦片合规 | 不得自行抓取/缓存/转发高德瓦片给第三方 |
| 地图数据出境 | 底图由高德境内节点提供，不得回传境外 |

> 若后续加入 POI 搜索、路线规划、地点分享等「互联网地图服务」能力，需重新评估是否涉及测绘资质或必须走图商合作方案，不能自行实现。

## 3. 推送

### 3.1 为什么不能用 FCM

| 事实 | 影响 |
|---|---|
| 国产 Android 无 GMS | `FirebaseMessaging` 拿不到 Token，直接不可用 |
| 厂商清理后台长连接 | 即使有 GMS 也会丢消息 |
| Traccar `firebase` notificator 依赖 Google 服务账号 | 只能服务海外用户 |
| Crashlytics / Analytics 同样依赖 GMS | 中国大陆需换 Bugly / 友盟 |

**结论：FCM 只保留在海外 flavor，中国大陆包必须走厂商通道。**

### 3.2 方案对比

| 方案 | 到达率 | 成本 | 工期 | 结论 |
|---|---|---|---|---|
| 极光 JPush（聚合厂商通道） | 高 | 免费额度 + 商用付费 | 2–3 天 | **采用** |
| 个推 / 友盟 | 高 | 类似 | 2–3 天 | 备选 |
| 自建长连接 | 低（被杀即断） | 服务器成本 | 2 周+ | 不采用 |
| 仅本地通知 | 无（App 不运行就收不到） | 0 | 0 | 仅兜底 |
| FCM | 中国大陆≈0 | 0 | 0 | 仅海外 |

### 3.3 目标架构

```
┌────────────┐   event    ┌──────────────────┐   alias   ┌──────────┐
│  Traccar   │ ─────────► │  推送网关 (BFF)   │ ────────► │  JPush   │
│ Notificator│  HMAC      │ 去重/限流/模板     │  REST     │  极光     │
│  Webhook   │            │ 别名 -> 用户       │           └────┬─────┘
└────────────┘            └──────────────────┘                │
                                                        厂商通道
                                          ┌──────────────────┼───────────────┐
                                          ▼                  ▼               ▼
                                       小米/红米           华为/荣耀        OPPO/vivo
                                          └──────────────────┼───────────────┘
                                                             ▼
                                                      TrackerOne App
```

为什么中间要加网关，而不是 Traccar 直接调极光：

1. **不把 Master Secret 放进 Traccar 配置**（Traccar 配置常被运维共享）；
2. 可以做事件去重、免打扰、合并、限流、模板与多语言；
3. 可以做到达/点击回执与看板；
4. 未来换推送供应商只改网关，不动 Traccar 与 App；
5. 支持一个用户挂多个 Traccar 服务器（alias 带 `serverId`）。

### 3.4 别名规范

```
alias = u{traccarUserId}@{traccarServerId}
例：u1@1
```

- App 登录成功后调用 `PushService.initialize(userId, serverId)`；
- 退出登录调用 `DELETE /v1/aliases/{alias}`；
- 换账号/换服务器必须重新注册，避免消息串号；
- Traccar 侧**不再**把推送 Token 写进 `user.attributes.notificationTokens`（那是 FCM 方案）。

### 3.5 消息类型

| 类型 | data 字段 | App 行为 |
|---|---|---|
| 事件通知 | `eventId`, `deviceId`, `type` | 通知 + 点击进 `/event/:id` |
| 远程指令 | `command`（`positionSingle` 等） | 后台执行，不弹通知 |
| 静默同步 | `sync` | 触发一次增量拉取 |
| 公告 | `noticeId` | 打开公告页（P1） |

字段统一放在 `extras`，App 用 `PushMessage.fromData` 解析。

### 3.6 厂商通道资质（关键路径）

| 厂商 | 要求 | 提前期 |
|---|---|---|
| 小米 | 小米开放平台企业开发者、应用签名 + 包名 | 3–5 工作日 |
| 华为 / 荣耀 | 华为开发者联盟企业认证、AGC 应用、签名证书 | 5–10 工作日 |
| OPPO | OPPO 开放平台企业认证、包名 + 签名 | 3–7 工作日 |
| vivo | vivo 开放平台企业认证 | 3–7 工作日 |

> 个人开发者通常**无法**开通全部厂商通道。若以个人主体发布，到达率会明显下降，
> 需在隐私政策与产品文案中说明「锁屏后可能延迟收到告警」。

### 3.7 到达率优化

- 首次进入地图后再申请通知权限（不要启动即弹）；
- 引导加入电池优化白名单（`docs/05` 第 6.3 节）；
- Android 通知渠道分级：告警（高）/ 状态（低，不可滑除）；
- 同一设备 1 分钟内多条事件合并为「N 条新告警」；
- 免打扰时段只入库不推送；
- 推送失败降级：App 前台用 WebSocket，冷启动用 `/api/reports/events` 补拉。

### 3.8 服务端改造

见 [`server/README.md`](../server/README.md)：

1. `NotificatorWebhook.java` 放入 `org.traccar.notificators`；
2. `NotificatorManager` 注册 `"webhook"`；
3. `notificator.types` 加入 `webhook`；
4. 通知规则选择 `webhook`；
5. 网关校验 HMAC + 幂等 + 调极光。

> 这是对 Traccar 的**自维护补丁**。升级 Traccar 时必须重新应用；
> 若不接受维护分支，备选是网关轮询 `/api/reports/events`（有延迟与配额成本）。

### 3.9 构建隔离（提审前必须处理）

当前 `pubspec.yaml` 同时包含极光与 Firebase。中国大陆包在**运行时**不会初始化 Firebase，
但 APK/IPA 中仍会打包 Firebase 原生库与相关组件。商店隐私检测可能因此要求说明，
甚至判定存在未声明的 SDK。

上线前二选一：

| 方案 | 做法 | 评价 |
|---|---|---|
| A. 拆分 CN 依赖（推荐） | 维护 `pubspec_cn.yaml` 或独立 CN 分支，移除 `firebase_*` 与 FCM 代码 | 最干净，能通过最严格的检测 |
| B. 保留但禁用 | 不提供 `google-services.json`，`PUSH_PROVIDER=jpush`、`CRASH_REPORTER=none`，并在 SDK 清单声明 | 有被质疑风险 |

CN 包 CI 建议加一步检查：

```bash
unzip -l build/app/outputs/flutter-apk/app-release.apk \
  | grep -Ei 'firebase|gms' && echo 'CN 包仍包含 Firebase，需拆分' && exit 1 || true
```

> 在完成拆分前，不要把 CN 包提交商店审核。

## 4. 合规与备案

### 4.1 APP 备案（硬门槛）

| 项 | 说明 |
|---|---|
| 依据 | 工信部《关于开展移动互联网应用程序备案工作的通知》（2023） |
| 现状 | 已实施：未备案 App 不得在国内从事互联网信息服务，商店不予上架 |
| 办理 | 通过**云服务商/接入服务商**备案系统，或应用商店代备案 |
| 材料 | 主体证件、负责人身份、App 名称与包名、域名、服务器 IP、隐私政策、承诺书 |
| 周期 | 1–20 个工作日，通常 5–10 |
| 结果 | 备案号，格式如 `京ICP备xxxxxxxx号-1A`（A 表示 App） |
| 展示 | 必须在 App「关于」页展示备案号 |

> 备案是**上线前置条件**，不是上线后补。它同时决定商店能否提审。

### 4.2 域名与 ICP 备案

- 服务端域名在境内 → 必须完成 **ICP 备案**（非经营性）且域名实名；
- 使用境外服务器 → 延迟高、合规风险大，不推荐面向国内用户；
- HTTPS 证书、等保（如涉及大量个人信息）按客户/规模评估。

### 4.3 个人信息保护

本 App 处理的核心数据是**行踪轨迹**，属于《个人信息保护法》定义的**敏感个人信息**。

| 要求 | 落地 |
|---|---|
| 告知同意 | 首次启动展示隐私政策，勾选后进入 |
| 单独同意 | 开启「后台定位上报」前单独弹窗，说明频率、目的、接收方（服务器地址） |
| 最小必要 | 不采集通讯录、短信、应用列表；位置精度按场景降级 |
| 权限时机 | 不得首次启动申请后台定位；用户点「开始上报」时才申请 |
| 第三方 SDK 清单 | 高德地图、极光推送、Bugly（待定）、Flutter 插件 |
| 个人信息收集清单 | 位置、设备型号、系统版本、崩溃日志、推送标识 |
| 账号注销 / 数据删除 | App 内提供入口；服务端删除或匿名化 |
| 未成年人 | <14 岁需监护人同意；儿童定位场景需额外提示 |
| 数据出境 | 中国大陆包不使用境外 SDK/服务器；Firebase 仅海外包 |
| 隐私政策 | 中文、可离线查看、含 SDK 清单与联系方式 |

**建议的首次启动顺序：**

```
欢迎页
  → 隐私政策（摘要 + 全文链接 + 同意/拒绝）
  → 同意后才初始化任何 SDK（地图/推送/统计）
  → 选择模式
  → 服务器配置
  → 登录
  → 权限向导（通知 → 前台定位）
  → 用户点「开始上报」→ 单独同意 → 后台定位
```

> `TrackerMapView` 已内置「先同意后加载地图」，不要绕过它直接使用 `AMapWidget`。

### 4.4 测绘与地图合规

| 要求 | 落地 |
|---|---|
| 使用有资质图商 | 高德（甲级，以官方公示为准） |
| 不自行生产地图数据 | 不自采道路、不自绘底图、不拼接瓦片 |
| 不向第三方提供地图数据 | 不导出瓦片、不转售 |
| 展示审图号 | 「关于」页展示当前底图审图号 |
| 坐标 | 展示层使用 GCJ-02，不把 GCJ-02 数据写入服务端 |
| 轨迹 | 属于用户个人信息，不得公开分享；分享需脱敏与授权 |

### 4.5 应用商店

| 商店 | 关键要求 | 备注 |
|---|---|---|
| 华为应用市场 | 备案号、软著/电子版权、隐私政策、SDK 清单 | 审核最严之一 |
| 小米应用商店 | 备案号、隐私检测、权限说明 | 对后台定位敏感 |
| OPPO 软件商店 | 备案号、隐私检测、测试账号 | 检测自动化程度高 |
| vivo 应用商店 | 备案号、隐私检测 | 同上 |
| 应用宝 | 备案号、软著 | 需提供测试账号 |
| 荣耀应用市场 | 备案号、隐私政策 | 与华为类似 |

**定位跟踪类应用的额外风险：**

- 商店会重点核查「是否跟踪他人、是否告知被跟踪人」；
- 必须在描述与隐私政策中写明「仅用于本人设备或已获授权的设备/家庭成员」；
- 提供「停止上报」「删除数据」入口，审核时会实际测试；
- 后台定位需提供录屏：开启 → 锁屏 → 服务端收到位置。

## 5. 排期影响

原 12 周排期假设「首发海外」。改为中国大陆后：

```
W-6  ──────────────  W-3  ──────────  W0
主体认证 / 域名 / 备案   软著 / 厂商通道   提审
        │                    │              │
        └── 与 Sprint 0-2 并行 ─────────────┘
```

| 变化 | 影响 |
|---|---|
| 备案前置 | 开发可以并行，但**提审必须等备案号** |
| 软著 | 30–60 天，需最早启动 |
| 厂商通道 | 1–2 周，影响推送到达率验证 |
| 隐私合规改造 | Sprint 1 增加约 3 人日（同意流、SDK 清单、权限时机） |
| 地图 SDK 替换 | 已用适配层隔离，Sprint 3 不变 |
| 推送网关 | 新增约 5 人日（服务端） |

**总工期：+2–3 周**（主要是等备案与软著，可与开发并行）。

## 6. 中国大陆风险登记

| ID | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| CN1 | 备案未完成导致无法上架 | 高 | 高 | 第 1 周即启动；并行开发 |
| CN2 | 厂商通道资质不足（个人主体） | 中 | 高 | 尽早注册企业主体；否则接受较低到达率 |
| CN3 | 隐私检测不通过（SDK 提前初始化） | 中 | 高 | 统一走 `TrackerMapView` 同意门；上线前用商店自检工具 |
| CN4 | 被判定为「跟踪他人」 | 中 | 高 | 明确授权文案、演示视频、删除入口 |
